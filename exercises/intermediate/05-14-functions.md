# Curated Lab Set

## Lab 1: Keyword arguments

**Objective:** Practice **Keyword arguments** by completing a small, testable task rather than only writing a demonstration.

**Task:** Write a reusable function with explicit parameters and a return value; avoid relying on global state. Build a solution specifically for **Keyword arguments**. Document the input you used and the exact output you obtained. Call the function with at least three inputs, including one boundary case, and show the returned values.

**Acceptance criteria:**
- Required behavior works for the stated example.
- Include at least 3 test cases: normal, boundary, and invalid/empty input where applicable.
- Output is deterministic and easy to verify manually.
- Use meaningful names and keep the solution scoped to the concept being practiced.
- Do not use machine-specific paths or hard-coded credentials.

**Challenge:** Add one extension that increases realism without changing the core requirement (for example validation, reusable functions, sorting, reporting, or a second input case).

**Interview question:** Why is **Keyword arguments** useful, and what common mistake would you watch for when implementing it?
