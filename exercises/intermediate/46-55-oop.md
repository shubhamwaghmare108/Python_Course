# Curated Lab Set

## Lab 46: Class attributes

**Objective:** Practice **Class attributes** by completing a small, testable task rather than only writing a demonstration.

**Task:** Model a small domain object with 2–4 attributes and at least two behaviors. Build a solution specifically for **Class attributes**. Document the input you used and the exact output you obtained. Demonstrate object creation, the requested OOP behavior, and one invalid/edge case.

**Acceptance criteria:**
- Required behavior works for the stated example.
- Include at least 3 test cases: normal, boundary, and invalid/empty input where applicable.
- Output is deterministic and easy to verify manually.
- Use meaningful names and keep the solution scoped to the concept being practiced.
- Do not use machine-specific paths or hard-coded credentials.

**Challenge:** Add one extension that increases realism without changing the core requirement (for example validation, reusable functions, sorting, reporting, or a second input case).

**Interview question:** Why is **Class attributes** useful, and what common mistake would you watch for when implementing it?
